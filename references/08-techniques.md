# 提示词技术与诊断（TQ）

这不是模板集，是写和改提示词的方法。用户说"效果不好"时来这里按症状查。

---

## 一、所有框架其实在回答同一个问题

网上流传的框架很多，名字不同，拆开看都是同一组变量的不同切法。

| 框架 | 变量 | 特点 | 什么时候用 |
|---|---|---|---|
| ICIO | 指令 / 背景 / 输入 / 输出 | 最简，四个字段平铺 | 单点任务，30 秒写完 |
| CO-STAR | 背景 / 目标 / 风格 / 语气 / 受众 / 输出 | 把风格和受众拆开 | 写作、文案、报告，日常通用 |
| CRISPE | 能力与角色 / 洞察 / 陈述 / 个性 / 实验 | 多一个"给我多种方案" | 需要方案对比、头脑风暴 |
| BROKE | 背景 / 角色 / 目标 / 关键结果 / 迭代 | 目标升级成可衡量的结果 | 要钉死目标、多轮打磨 |
| LangGPT | 角色 / 简介 / 目标 / 技能 / 规则 / 流程 / 初始化 | 完整的角色设定，可复用 | 长期反复使用的助手设定 |

各来源对缩写的展开略有差异。框架用于提醒变量，不能替代真实任务的验收；角色等变量并非每次必需。

把上面全部拆开去重，实际只有六个变量：

1. **背景** — 谁、在什么处境、手头有什么
2. **角色** — 让模型调用哪部分知识（"资深审稿人"和"科普作者"调用的是不同的知识分布）
3. **任务** — 交付什么，一个动词开头
4. **约束** — 边界在哪，必须做什么、不能做什么
5. **格式** — 结果长什么样，给骨架或样张
6. **出口** — 不确定时怎么办

前四个决定输出对不对，后两个决定输出能不能直接用。多数人只写前三个，所以拿到的结果总是"方向对但没法用"。

## 二、约束怎么写才管用

约束是最容易被写废的部分。常见三种废法：

**废法一：形容词当约束**
"写得专业一点""简洁有力""要有深度"——这些词对模型没有信息量，它不知道你要的是哪种专业。

改成可检验的：`每段不超过 150 字`、`有数据依据的结论注明数据与来源，无数据时不强凑数字`、`不出现"综上所述"`。

**废法二：只写禁止，不写正面要求**
"不要空洞""不要套话"——模型知道不该做什么，但不知道该怎么填那个位置，结果只是换一种套话。

正面要求更有效。把"不要空洞"换成"有真实材料支持的论点配可核实案例及来源；没有证据就说明缺口，不编造公司和数字"。

**废法三：约束互相打架**
"200 字以内"加"详尽展开"，模型只能二选一或者给个四不像。写之前自己检查一遍有没有互斥。

禁止项的正确用法是**堵默认坏习惯**，不是表达偏好。模型在每个领域都有固定套路：写文案爱用"赋能""闭环"，写论文爱用"随着…的发展"，写建议爱说"要自信"。把这些具体套路列出来禁掉，效果立竿见影；禁"不要写得差"没有任何作用。

## 三、示例怎么放

示例可用于说明格式与判断标准，是否改善效果需按本任务验证。

三条经验：

- **数量按任务验证**。先选少量典型及边界示例，再根据真实输出增减；没有通用的三个上限。
- **位置和标识清楚**。将示例与材料、指令分开，并说明哪些特征要模仿；位置根据模型和上下文长度验证。
- **必要时给正反例**，明确标记禁止模仿的部分；是否优于只给好例需要在本任务验证。

示例要覆盖边界情况。只给典型样例，遇到非典型输入模型就自由发挥。

## 四、要不要让模型"一步步想"

推理型模型（会自己展开思考过程的那类）不需要你写"请一步一步思考"。写了反而可能干扰它原本的推理路径，或者让输出变啰嗦。

对普通模型，触发推理有效的三句话是：

- `在给出结论前，先列出你的判断依据，再给结论`
- `说明你排除了哪些方案，以及为什么排除`
- `风格偏好可说明默认值；缺关键事实则标注未提供，暂停依赖该事实的判断，继续可完成部分`

假设不能代替关键事实。需要对话反馈的任务保留追问；用户不希望追问时输出待确认项，而不是制造答案。

## 五、长文本怎么处理

一次性丢十万字进去，模型对中间部分的注意力会下降，这是普遍现象。

三个做法：

**分段读，每段锚定**
```
这是材料第 1 部分（共 4 部分），只做一件事：提取其中的关键数据和结论，列成清单，不要分析。
```
每段只给一个动作。各段保留来源与位置，再按需回查原文统合；只抽关键数据可能丢失限定条件，需要和整篇任务比较。

**关键约束在结尾重复一次**
长上下文里，开头写的约束容易被后面内容冲淡。把最重要的两三条在末尾再说一遍。

**先建索引再读细节**
材料很长时，第一轮只要目录和结构，第二轮再按需深入某一部分。

## 六、降低编造

模型编造内容，多数时候不是因为"想骗你"，是因为任务要求它必须给出一个答案，而它没有。

所以最有效的手段是**给它一个体面的出口**：

```
不确定的地方标注"待核实"，不要猜测。
材料里没有的信息，写"材料未提供"，不要补充。
无法核实文献是否存在时，不写作者、年份、题名或DOI，只给检索方向。核查真实来源后才列引用。
```

第二条比第一条更硬。"标注待核实"还留了编造空间，"写材料未提供"则明确禁止补充。

另外两个手段：

- **限定来源**：`只使用我提供的材料回答，不要引入外部知识`
- **要求可回溯**：`每个结论后面注明依据是原文哪一段`

## 七、效果不好怎么改

不要重写。按症状定位，一次只改一个变量，改完立刻验证。同时改三处，你不知道是哪处起的作用。

| 症状 | 病因 | 改法 |
|---|---|---|
| 内容空泛，全是正确的废话 | 缺具体约束和素材 | 有真实材料时配案例/数字与来源；没有就列证据缺口 |
| 结构混乱，想到哪写到哪 | 没给输出骨架 | 在结尾给出分节标题和每节字数 |
| 太长，重点被淹没 | 只给了上限没给结构 | 改成"分 N 节，每节不超过 X 字"，并指定哪节最重要 |
| 太短，该展开的没展开 | 没指定展开位置 | 指出"第二节需要展开到 500 字，包含三个层次" |
| 编造文献、数据、案例 | 没有出口 | 加"不确定标注、材料未提供不要补充" |
| 明显不懂这个领域 | 角色太泛或术语没给 | 补充任务职责、领域标准与实际术语，不虚构年限 |
| 每次结果差异很大 | 约束太松 | 固定结构和判定标准，给出好例坏例 |
| 回答在打太极，不给结论 | 没要求立场 | 证据足够时推荐并说明失效条件；不足则列决策所需信息 |
| 开头总是"在当今时代" | 没禁默认开场 | 明确禁止，并指定第一句必须写什么 |
| 三个方案看起来差不多 | 没要求差异化 | 要求"三个方案必须在 X 维度上不同，说明各自牺牲了什么" |

改完一轮仍失败时，检查输入、约束、工具和模型能力，而不是直接断言原因；可能的边界包括（需要实时数据、需要看你没给的文件、需要专业判断）。这时候换工具比改提示词有效。

## 八、几个容易忽略的细节

**角色给具体身份，不给形容词**
写清任务职责和领域标准，例如"按医疗器械注册要求检查材料缺项，并标明依据"；无需虚构从业年限、资质或处理数量，角色设定不保证事实准确。

**任务用动词开头，说清交付物**
"帮我看看这段代码"和"检查这段代码的安全问题，只报告有依据的问题，每处给行号、触发条件和改法；允许零个"，产出完全不同。

**格式给骨架，不给描述**
"结构清晰"无用。直接给：
```
一、结论（一句话）
二、依据（按实际证据列出，能核实的数据才引用）
三、风险（有依据的风险，不凑数量）
```
模型照着填，你不用返工。

**中英混用的任务，术语给对照**
技术类任务里，让模型在第一次出现术语时附英文原词，能显著减少理解偏差。

**对话长了要重新锚定**
超过十几轮后，模型对最初设定的记忆会变淡。加一句"重申一下要求：…"，比重新开一个对话省事。

## 九、贴出去之前的自检

七条，每条都能用一句话回答：

1. 任务职责和领域标准清楚吗？角色是否必要，有没有虚构资历
2. 背景够吗？模型知不知道我是谁、手头有什么、产出拿去干嘛
3. 任务是动词开头的明确动作吗？交付物说清了吗
4. 约束可检验吗？有没有形容词冒充约束
5. 约束之间打架吗
6. 输出格式给了骨架还是只给了描述
7. 有没有留"不确定怎么办"的出口

这七条是文本检查，不能证明实际效果；再用真实任务、边界输入和无材料场景试用，记录实际输出与编辑成本。
