# 统一清单维护

仅在新增、修改或检查模板库时读取。日常生成提示词只需读取索引与相关模板，不需要加载整份JSON或运行脚本。

## 编辑入口

`templates.json` 是模板元数据的唯一来源，包含 `schema_version: 1`、分类列表 `categories` 和模板列表 `templates`。提示词正文与尾注仍在分类Markdown中维护。

| 字段 | 含义及编辑规则 |
|---|---|
| categories.key/name/file | 分类标识、显示名称、正文位置；分类file为references下的Markdown文件，不可指向生成索引 |
| key | 关联正文的稳定标识，如ac-01；与正文注释 `<!-- template: ac-01 -->` 一一对应。正常改名、改展示编号时保持不变 |
| id | 展示编号，如AC-01；同分类连续且唯一，前缀对应分类。改编号只改清单即可同步生成的正文标题和索引；正文、尾注或入口中的手写交叉引用仍需核查，生成器不擅自改写它们 |
| category | 分类key |
| name/level/use | 名称、L1/L2/L3深度、适用场景；档位不代表固定回复行数 |
| materials.required | 实质执行的最低材料或任务输入，不等于提示词交付前一定要收齐；缺少时执行降级分支 |
| materials.optional | 有助于判断但不阻塞核心任务的补充材料；不能把实际必需输入一律放可选 |
| network.mode | none无需联网；conditional满足指定条件时须检索；required任何情况下都必须联网。个人病史、实际代码、医嘱等缺口不能用联网猜填 |
| network.condition | none时必须为空字符串；其他模式写明何时、为何要联网，不只写“可能需要” |
| fallback.missing_materials | 缺执行对象时给什么：框架、待补清单或可支持部分；陪练等无需材料的任务可直接开始 |
| fallback.offline | 无联网工具时如何处理外部事实；不能假装检索过，不能从外部查到用户未提供的个人事实 |
| fallback.missing_facts | 关键事实未知时暂停哪些结论，以及仍能做什么；不能默认法域、剂量、库存或源数据 |

生成索引显示材料要求、联网模式与缺材料降级；正文顶部显示全部字段，包括可选材料、联网触发条件与三个降级分支。它们是生成内容，不手工改。

## 常用操作

在skill目录执行：

```text
node scripts/catalog.cjs --write
node scripts/catalog.cjs --check
node --test tests/catalog.test.cjs
```

`--write` 先验证整份清单与全部正文绑定，发现错误则不写文件；验证通过后只更新索引和各模板的顶部元数据，保留复制块及尾注。`--check` 仅读取，不自动修改；生成内容漂移时提示重建。多个输出文件逐个写入，不声称是跨文件原子事务，更新前仍宜备份。

新增模板：在对应Markdown中增加稳定key注释、现有格式的标题及“用在”行、一个完整text复制块和尾注；再向清单添加同key的条目并填齐字段。标题只需先符合格式，展示名称和档位会按清单重建。不能只往清单加一行而没有提示词正文。

修改依赖时，同时核对提示词正文中的假设和信息不足处理；生成器不会根据清单悄悄重写提示词。若清单声称离线可执行，而正文仍强制真实外部数据，需要人工解决冲突。

测试覆盖清单驱动生成、只读、幂等、正文保留和错误拒绝，不证明全部模板的实际效果或材料依赖语义完全正确。批量迁移还应与备份对照key集合、模板数量和复制块字节。
